# Security / Realtime監査状況

## 対応済み

- production・`ENVIRONMENT` 未設定/未知値でのSecret・初期Teacher fail closed
- Teacher JWTによるRoom/Teacher管理API保護
- 単一Worker管理Supabase ProjectとRoom URLの正規化後一致強制
- Private Channel + custom JWT + `realtime.messages` RLS migration
- Student JWTのRoom境界、別Room JWT拒否
- Studentの直接Broadcast禁止、Worker relay、claim由来本人情報
- Teacher main + Inboxの両方を必要とするonline判定
- Student/Teacherの `CHANNEL_ERROR` / `TIMED_OUT` / `CLOSED`、retry callback、timer/unmount cleanup
- Teacher初期化途中のChannel cleanup
- relay non2xxの安全な内部ログと一般化された外向きエラー
- stable error codeとRunbook
- Room保存、受付ON/OFF、relay、Realtime失敗・再接続の回帰テスト

## 本番導入前の外部作業

- Supabase migration適用、`realtime.messages` Policy確認
- Realtime Settings **Allow public access OFF**
- Worker production variables/Secrets設定
- RLSのnegative test（別Room、Teacher Inbox、Student INSERT）
- Keep AliveのRepository Secrets登録と手動実行確認

詳細は [`docs/realtime_authorization_setup.md`](./docs/realtime_authorization_setup.md) と [`docs/troubleshooting.md`](./docs/troubleshooting.md) を参照してください。

## 既知の残存リスク・今回スコープ外

- Teacher app JWTのlocalStorage保持（HttpOnly Cookie化は将来候補）
- Teacher login rate limitはWorker isolate内であり、全PoP一貫の分散制限ではない
- 現行legacy Supabase anon/service role/JWT secretから新key/Signing Keysへの移行
- Studentチェックインは強い本人確認ではない

これらを理由にRLS、JWT境界、production fail closedを弱めてはいけません。Student回答履歴・CSV archiveは現行機能ではなく、新規保存も行いません。
